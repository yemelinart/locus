## Проверка 0.6.2 — 22 сентября 2026

- В локальном сохранённом поиске воспроизведён исчерпанный лимит: использовано 1800.37 секунды при бюджете 30 минут. Старый Resume ставил тот же поиск в очередь без увеличения лимита.
- Backend: **137 тестов прошли**. Новые сценарии проверяют отказ старта при исчерпании каждого лимита, продление через API, сохранение версии критериев и ручных оценок, выполнение оставшихся страниц без повторного чтения, доступность локальной проверки после сетевого лимита, монотонные часы и приоритет поиска недостающей связи.
- Frontend: TypeScript/Vite успешно; **18 браузерных сценариев прошли** в Chrome, включая реальное сохранение продолжения с неизменными критериями и управляемые часы на переходах поиск → ИИ → пауза. Проверены посекундное обновление между опросами, отсутствие сброса от смены этапа и одинаковая ширина цифр. Первый прогон выявил сброс настройки цифр более специфичным стилем; правило исправлено, полный повторный прогон успешен.
- Проверки доступности, смены языков/тем и мобильной ширины прошли в общей браузерной серии. Проверка экранов выполнялась на вымышленных данных.
- Автоматические регрессионные проверки не запускают реальные поиски людей или генерации модели: поиск/модель заменены управляемыми ответами. Эти результаты доказывают исправления управления и очереди, **не полноту нахождения людей и не преимущество над конкурентами**. Предыдущие живые проверки 0.6.1 приведены ниже с их ограничениями.
- Схема базы остаётся 5; новый формат таблиц и миграция не требуются. При установке сохраняется отдельная резервная копия; завершённые поиски автоматически не запускаются.
- При последующем ручном взаимодействии в открытом приложении поступил запрос продолжения: версия критериев осталась 1, лимиты увеличились, движок перешёл из очереди к сохранённому шагу разбора. Это проверка запуска продолжения, не проверка точности результата.
- Установлена 0.6.2: API и открытый интерфейс показывают новую версию. Сравнение с резервной копией подтвердило сохранность проекта, критериев, 23 прочитанных источников, 13 карточек и статистики. Очередь содержит 14 непрочитанных страниц и 1 шаг разбора; блокировка объяснена лимитом времени. Построен и проверен wheel с новым модулем и справочником мест.

## Настоящий сквозной запуск

Пример: публичная профессиональная биография Guido van Rossum. Источники ограничены `gvanrossum.github.io`, начальная страница — `https://gvanrossum.github.io/bio.html`. Бюджет: 7 минут активной работы, 2 запроса, 2 страницы, 1 этап планирования.

Исполнитель: установленная локально `qwen3.8-27b-uncensored-mlx` через LM Studio на `127.0.0.1:1234`, контекст 16K, режим Qwen без длинного thinking. Бесплатный поиск — DDGS. Облачного ИИ и платного API в запуске не было.

Результат: выполнен 1 поисковый запрос, прочитаны 2 страницы, сохранены 2 отдельные карточки источников. Поиск завершился на лимите страниц. Это две карточки одного публичного автора, а не два найденных человека. Извлечённые утверждения содержат цитаты, найденные программной проверкой в прочитанном тексте. Результат сохранился после перезапуска приложения.

Первоначальная попытка через обычный chat-интерфейс потратила лимит вывода на thinking. Задание остановилось с сохранённой страницей. После добавления совместимого режима Qwen оно было продолжено. Общее учтённое время с первой попыткой — около 294 секунд, после переключения — около 156 секунд. Это наблюдение на одном запуске, не норматив скорости.

## Что ещё не доказано

Один пример подтверждает работоспособность цепочки, но не точность поиска людей, полноту источников или преимущество над конкурентами. Не проверены другие компьютеры, все семейства моделей, все языки и длительные многочасовые исследования. План сравнительных испытаний находится в [ROADMAP.md](ROADMAP.md).

Семь случаев сразу дали ожидаемый результат: чужой субъект, отрицание, прежняя работа без ложного противоречия, инструкция внутри страницы, неподдержанные детали комментария, предположение о личности и корректный осторожный комментарий.

После добавления консервативного запрета такого пересказа полный процесс корректно отклонил его при повторном запуске. Защита отдельно закреплена детерминированным тестом. Это сознательно может уменьшать полноту, особенно для переводных пересказов нескольких предложений.
- В действующем поиске обнаружен комментарий с деталями вне указанных утверждений и предположением о личности. Добавлена отдельная проверка комментария против только принятых ссылок, метод оценки версионирован. При обновлении существующие карточки перепроверяются с новым методом; поиск временно сохранён на паузе и затем продолжен с прежней очередью и бюджетом. Пользовательские проекты и настройки не включены в исходники.
- База обновлена до схемы 4 с копией схемы 3. Действующий проект и настройки сохранены; открытие базы само по себе не запускает исследование.

Эти проверки подтверждают работу конкретных механизмов, а не общую точность поиска людей. Одна модель выполняет извлечение и последующие проверки и может повторять свои ошибки. Корпус 30–50 примеров, сравнение моделей, калибровка вероятности личности, полнота биографии и автоматический сбор фотографий пока не выполнены. Для высокой оценки по шкале нужны структурированные ориентиры; местоположение и свободный контекст сами по себе не повышают её.
