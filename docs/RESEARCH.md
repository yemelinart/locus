# Изученные решения

Проверено 2026-09-21. Это выборочный обзор подходов, не исчерпывающий аудит рынка и не сравнение точности платных продуктов.

| Решение | Подтверждённый подход | Вывод для Locus |
|---|---|---|
| [Vane (ранее Perplexica)](https://github.com/ItzCrazyKns/Vane) | Локальные/облачные провайдеры, SearXNG, режимы поиска и источники; MIT | Удобное поисковое приложение уже можно собрать на открытых компонентах. Специализированную проверку кандидатов всё равно нужно разрабатывать и измерять |
| [Архитектура Vane](https://github.com/ItzCrazyKns/Vane/blob/master/docs/architecture/README.md) | Отдельно описанный поисковый процесс и работа провайдеров | Сохранять границы между интерфейсом, поиском, чтением и моделью |
| [GPT Researcher](https://github.com/assafelovic/gpt-researcher) | Планирование исследования, сбор источников и отчёты; Apache-2.0 | Заимствовать принцип итеративного исследования, но не делать Locus зависимым от облачных конфигураций quickstart |
| [SearXNG](https://docs.searxng.org/dev/search_api.html) | Метапоиск с HTTP API, языками и фильтрами | Необязательный локальный адаптер; не является собственным полным индексом интернета |
| [DDGS](https://github.com/deedy5/ddgs) | Метапоиск через несколько служб без обязательного API-ключа; MIT | Небольшая зависимость для первого запуска без Docker. Ошибки и ограничения источников должны оставаться видимыми |
| [LM Studio](https://lmstudio.ai/docs/developer/openai-compat) | Локальный совместимый API, модели и structured output | Подключаемый локальный исполнитель; качество схем и reasoning проверяется на конкретной модели |
| [WhiteBridge](https://whitebridge.ai/) | Коммерческие отчёты по публичным источникам; оговорка о неполноте и отсутствии гарантии точности | Маркетинговое число источников не использовать как метрику качества. Платный отчёт не покупался, точность не измерялась |

Отдельно изучены [structured output LM Studio](https://lmstudio.ai/docs/developer/openai-compat/structured-output), [список моделей](https://lmstudio.ai/docs/developer/rest/list), [управление загрузкой](https://lmstudio.ai/docs/developer/rest/load), [запуск loopback-сервера](https://lmstudio.ai/docs/cli/serve/server-start), [Tauri](https://v2.tauri.app/) и [подписанные обновления](https://v2.tauri.app/plugin/updater/).

## Гипотезы улучшения — ещё не доказанные преимущества

1. Увеличить точность за счёт запрета автоматического слияния тёзок, явных противоречий и ручного подтверждения.
2. Сделать доказательства доступнее: связать утверждение с конкретным текстом страницы и временем чтения.
3. Снизить повторную работу за счёт сохранённой очереди и прочитанных страниц.
4. Дать пользователю наблюдаемое управление бюджетом и полную картину отказов источников.
5. Поддерживать только локальную модель, не скрывая сетевые обращения поиска.

## Проверка конкурентоспособности

До любого заявления «лучше» нужен заранее зафиксированный набор минимум из 30–50 согласованных тестовых профилей или публичных профессиональных биографий. Включить тёзок, несколько алфавитов, неполные сведения и случаи, где правильный ответ — недостаточно данных. Разделить примеры для настройки и независимой проверки. Сравнить ручной поиск и открытые решения при одинаковом времени и исходных данных.

Основные метрики: ошибочные отождествления, корректные профили, доля утверждений с реальным подтверждением, пропущенные заранее известные публичные сведения, разнообразие независимых источников, время и нагрузка на Mac. Не использовать объём текста отчёта как показатель качества. Недоступные источники учитывать отдельно от случаев, когда человек не найден.

DeepResearch — неоднозначное название; конкретный продукт пока не указан и не оценивался.
